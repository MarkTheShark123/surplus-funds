# Garden State Surplus Recovery

This is a five-page, client-interactive marketing prototype for a New Jersey foreclosure surplus recovery company. The working brand is Garden State Surplus Recovery. The user has not approved public publishing or a custom domain. Do not deploy publicly, connect a domain, or activate live inquiry handling without approval.

## Architecture

- `src/routes/`: TanStack file routes for `/`, `/how-it-works`, `/about`, `/faq`, and `/contact`, plus the root HTML document and metadata.
- `src/components/Pages.tsx`: the five page bodies and educational content.
- `src/components/SiteLayout.tsx`: shared header, working brand mark, mobile navigation, footer, page introductions, eligibility links, and closing CTA.
- `src/components/EligibilityForm.tsx`: isolated client-only sample form with accessible validation and demo completion. Form state is transient React state; there is no persistence or network submission.
- `src/components/FAQAccordion.tsx`: native details/summary accordions and client-side category filters.
- `src/components/Icon.tsx`: small inline SVG icon system.
- `src/components/NotFoundPage.tsx`: branded 404. `src/router.tsx` adds the safe error fallback.
- `src/data/site.ts`: root page/social title and description. `src/data/faqs.ts`: the FAQ content and categories.
- `src/styles.css`: palette, typography, layouts, breakpoints, and reduced-motion support.
- `public/img/new-jersey-home.png`: generated illustrative photography, served via Netlify Image CDN. It is not a real company property or office.
- `public/robots.txt` and root metadata discourage indexing during review. These do not enforce private access.
- `netlify.toml` and `vite.config.ts`: scaffolded TanStack Start configuration, Vite, and Netlify adapter. No custom server is needed for this prototype.

## Conventions

Use React function components, TypeScript, typed TanStack links, and file-based routes with per-page metadata. The route tree is generated by the framework and must not be hand-edited. Use the existing CSS variables, DM Sans body type, Instrument Serif headings, deep navy, warm white, and muted green. Keep mobile touch targets usable, provide visible keyboard focus, retain native form labels, and respect reduced motion.

Keep all prototype disclosures accurate. Never imply that a demo submission reached a person, that records were checked, or that eligibility was established. Do not add unverified attorneys, business facts, credentials, testimonials, results, fees, or guaranteed outcomes. The legal business name, contact details, professional credentials, and fee structure are placeholders until verified. No live form registration exists.

## Future service integration

If real inquiries are requested, use the relevant Netlify platform skills and primitives. Do not persist inquiries in browser storage, local files, or transient server memory. Review consent, privacy, fee, and service disclosures before enabling a live workflow. Preserve the user’s requirement for launch approval.

## Development

Install with `pnpm install`; use `netlify dev --port 8889` for local image optimization support when local execution is permitted. Build uses the existing `build` script. Follow the active run’s restrictions: the initial implementation prohibited running builds, development servers, tests, or type checks; validation was limited to reading edited files, with automated validation left to the platform. Do not carry that run-specific restriction into future sessions if superseded.
